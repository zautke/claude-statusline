# Radial percentage indicators — design

Date: 2026-11-13. Status: approved by the user in session.

## Intent

The status line shows each percentage (context, disk, 5h, 7d, Fable) as a
horizontal heat-map bar. The user wants the option of a radial indicator: a
ring whose arc length is the percentage, in 1% (3.6°) steps, coloured with
the same continuous green → yellow → orange → red hue as the bars.

## Goals

- A ring glyph per percentage, 101 states (0–100).
- Colour from the existing `heat_rgb` ramp, unchanged.
- Works in iTerm2 (largo, macOS) and Windows Terminal (adagio).
- Users without the font keep today's output.

## Non-goals / anti-goals

- No gradient along the arc inside one ring (a monochrome glyph has one colour).
- No pixel-graphics protocols (kitty, sixel, iTerm2 inline images).
- Must never print missing-glyph boxes for a user who has not opted in.

## Constraints

- Claude Code re-renders status line stdout and keeps only text, SGR colour
  and OSC 8 links; image escape sequences are dropped.
- No Unicode or Nerd Font set has arcs finer than 8 steps.
- bash and PowerShell scripts must behave identically.

## Approaches

1. **Stock glyphs** (`○◔◑◕●`, Nerd Font `circle_slice_1..8`): 5 or 8 steps,
   filled pies rather than rings. Rejected: far from 3.6° resolution.
2. **Kitty graphics with Unicode placeholders**: pixel-exact, but neither
   iTerm2 nor Windows Terminal draws them. Rejected.
3. **Custom font with 101 ring glyphs** — chosen. Plain text plus colour, so
   it passes through Claude Code's renderer; costs a font install per machine.

## Design

- **Font:** generated by a Python script in the repo; the built font file is
  committed. Arc starts at 12 o'clock and sweeps clockwise. The unfilled part
  of the ring is absent.
- **Codepoints:** U+FFF00–U+FFF64 (agent's call: clear of Nerd Fonts'
  ranges and of Apple SF Symbols, which own U+100000 upward on macOS).
- **Width:** the terminal and Claude Code both count one cell per ring; the
  glyph is drawn wider than one cell and overflows into a trailing space the
  scripts always emit (agent's call: one cell is too narrow for 3.6° steps).
- **Emission:** raw UTF-8 bytes (`F3 BF BC+p/64 80+p%64`); macOS bash 3.2 has
  no `\U` escape.
- **Font name:** explicit PostScript name `StatuslineRings-Regular`.
- **Switch:** config setting `style: bar | ring`, default `bar` (agent's
  call). Percent text stays next to the ring.
- **Code touched:** `bar()` in `scripts/statusline-command.sh`, `Get-Bar` /
  `Get-FitBar` in `scripts/statusline-command.ps1`, both install scripts
  (font install), `statusline.example.json`, README, tests.

## Spike results (2026-11-13/14, largo)

- iTerm2 3.7.7 and Terminal.app draw the rings through system font fallback
  with no terminal configuration. A terminal that was already running when
  the font was installed must be restarted first.
- Inside a real Claude Code 2.1.325 status line the rings render, keep their
  colour, and are counted as one cell each.
- Rings at the spike geometry are small and sit tight against the next
  character; geometry and trailing padding need tuning.

## Still open
